-< front-end >-
   
<typing>
 > when user start typing a msg, get the (to-id(recipient) & fro-id(sender)) and trigger a typing event that the server can get/listen to.
  
 <save-chat>
 > when a user sends a message, get (to-id(recipient) & fro-id(sender) & the message) and trigger a `save-chat-request` event that the server can get/listen to.
   if server respond with without error in payload withall data sent, append the chat to existing conversations list.
  
 <fetch-chat>
 > when a chat-list modal/page is opened. Get user-id and trigger a `fetch-chat-request` event that server-listens to, if server response is success with list of user's
   conversations, append this to front-end conversation-list ui.
  
<remove-chat>
 >if a user clicks del-chat btn, get (user-id & chat-id), then create a `remove-chat` event that the server listens/can respond to. 
  if response from server is success, remove that very chat box/container or update it's content to show it was deleted in front-end.

<update-chat>
 >if user clicks `eidt-chat-btn`, activate/replace that chat-box with input to accept the updated chat. Get this (user-id & this very chat-id & chat-content(updated).
  Create `update-chat` event that the server will know what to do. If the server responds with success, replace that very chat-box/content with the new updated chat.

<disconnect>
 >if the chat modal/page is closed/navigated away-from or user(recipient not logged-in), create a `disconnect` event to inform the server. If it respond with success, set their status to
  offline/away to inform others they're currently not avilable.

<connect>
 >if the chat modal/page is opened/navigated to or user(sender/user is logged-in), create a `connect` event to inform the server. If it respond with success, set their status to
  online now to inform others they're currently avilable now.
